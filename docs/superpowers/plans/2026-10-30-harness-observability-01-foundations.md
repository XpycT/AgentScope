# Harness Observability Foundations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Separate harness identity from model-provider pricing, calculate honest per-category API equivalents, and establish measured session facts and bounded compressed-rollout reading.

**Architecture:** Migrate the existing domain and every caller in one coherent cutover, retaining the existing worker/UI path. Keep provider-specific usage normalization in its adapter; use a shared price engine and pure measured-fact helpers. Bundled official data is read locally, and zstd is streamed without extraction.

**Tech Stack:** Rust stable/edition 2024, serde/serde_json, chrono, existing Ratatui/Crossterm and rusqlite; one justified streaming zstd decoder dependency.

**Spec:** [Approved design](../specs/2026-10-30-harness-observability-design.md), especially §§3, 6–10. Execute with the [master plan](2026-10-30-harness-observability.md); this stage is not the whole release.

## Global Constraints

- Observe only; no provider writes, network calls, orchestration, migrations, telemetry, daemon, Tokio, or persistent index.
- Preserve unknown/reported/derived/estimated/partial provenance; subscription API equivalent is not subscription spend. No blind snapshot summation or inherited child billing.
- One worker; slices are 256 records/rows, 8 MiB, or 100 ms. Records 1 MiB; pages 500 events/256 KiB; loaded event window 20,000; pending loads 16; exact ledger 100,000 entries/8 MiB.
- Metadata limits 100,000 source records/64 MiB; hydrated cache 2,000. Metadata probes 4 KiB prefix/32 KiB plain tail; root/child batches 50. Expanded zstd bytes consume budgets.
- Use synthetic temp stores, the fixed fixture clock, sanitized rendering and content-free Debug. No raw config/manifest dumps.
- No commits, pushes, releases or dependency installation while **writing** plans. Execution may add the decoder only for its task. Do not include automatic commit steps; git delivery needs separate user authorization.
- During execution, run focused red/green tests for each task, no full build/lint/formatter mid-flight. Run the four repository gates once after integrated implementation, as specified in the master plan.

## Review Focus

1. Two profile databases share the same session ID: identity must include database source, never merge the conversations (A1).
2. A subscription reports zero dollars but positive token use: retain the zero charge separately and show a positive API-equivalent estimate (A2).
3. A request crosses a tier/time boundary or lacks its timestamp: price the complete request with the evidenced card, never silently choose the wall clock (A2).
4. Request timing is missing, ≤100 ms, nonfinite, overlapping, or interrupted: never show infinite speed or invent full active time (A3).
5. A tiny compressed source expands enormously or is replaced during reading: budget expanded bytes, yield/cancel, and reject stale source locators (A4).

- `pub fn request_rate(observation: &UsageObservation) -> Option<f64>` and `pub fn measured_speed<'a>(requests: impl IntoIterator<Item = &'a UsageObservation>) -> SpeedSummary`. Only conversation requests and >100 ms finite durations with recorded positive output qualify. Request output includes/excludes reasoning according to normalized accounting; no double addition. The latest eligible request keeps its actual model, so UI can show age/mismatch rather than relabeling old throughput.
- `SpeedAccumulator::new(max_entries: usize) -> SpeedAccumulator`, `observe(&mut self, request: &UsageObservation) -> SpeedOutcome`, `revise(&mut self, request: &UsageObservation) -> SpeedOutcome`, and `snapshot(&self) -> SpeedSummary` implement streaming aggregation; `SpeedOutcome::{Counted, Revised, Duplicate, Uncountable}`. It keys contributions with the same request-identity resolver as `UsageLedger`. State holds running sums/counts, one latest timed request by recorded completion time, and a bounded map of compact speed contributions so an accepted revision subtracts the old output/duration and adds the replacement exactly once. Same identity with different values without `revise` is Uncountable, not a second request; replay is Duplicate; revising a missing/untimed target is Uncountable. A revision that adds previously missing timing moves coverage from untimed to timed without double counting. `measured_speed` remains the finalized-iterator convenience, not the revision path. Provider ownership/deduplication runs before observation.
- `ContextUsage { used: Option<u64>, capacity: Option<u64>, class: AggregationClass, recorded_at: Option<Timestamp>, model: Option<ModelDetail>, compaction_epoch: Option<String> }`. No generic totalTokens fallback.
- `CompactionObservation { id: String, timestamp: Option<Timestamp>, method: Option<String>, trigger: Option<String>, summary: Option<BoundedText>, before_tokens: Option<u64>, after_tokens: Option<u64>, duration_ms: Option<f64>, usage: Option<UsageObservation>, scope: CompactionScope, provenance: Provenance }`, `CompactionScope::{Event, Aggregate, Unknown}`. `CompactionSummary { observed: usize, history_complete: bool, known_cost_usd: Option<f64>, cost_scope: CompactionScope, unpriced: usize, latest: Option<CompactionObservation> }`; `pub fn compaction_summary<'a>(events: impl IntoIterator<Item = &'a CompactionObservation>, history_complete: bool, prices: &PriceSchedule, policy: ReferencePolicy) -> CompactionSummary` uses the same request-aware estimator on attributable usage, not a second ad-hoc pricing implementation.

Missing event association remains unpriced per-event even when an Aggregate amount is known; preview/details can label that known amount aggregate without pretending it priced the individual events.
