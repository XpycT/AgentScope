# Hermes Sessions, Compression and Native Subagents Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Read native Hermes state databases, including profiles, nested delegates and both rotation/in-place compression, with complete available conversation history and honest direct/main/auxiliary accounting.

**Architecture:** A native SQLite reader uses narrow fixed projections and a bounded pure lineage index. Compression segments form one stable logical conversation; delegates attach to any segment in their parent's chain. Aggregate usage reconciliation remains provider-specific and never feeds cumulative rows to a request-only ledger as if each were one API call.

**Tech Stack:** Rust stable/edition2024; existing rusqlite0.41.1 bundled/hooks, serde_json, same-file and tempdir fixtures. No new dependency or provider imports.

**Spec:** [Approved design](../specs/2026-10-30-harness-observability-design.md), especially §§5–10, and [master](2026-10-30-harness-observability.md). Depends on [plan01](2026-10-30-harness-observability-01-foundations.md) and [plan02](2026-10-30-harness-observability-02-discovery-ui.md).

## Global Constraints

- SQLite read-only/query_only/allowlisted tables, columns and functions; only documented ADR-0002 runtime WAL/SHM sidecar exception. Never migrate, repair, copy or import provider code; no auth/config-file reads or runtime network.
- Slices256 records/8MiB/100ms, record1MiB, pages500events/256KiB, loadedwindow20,000, pendingloads16, ledger100,000entries/8MiB. Metadata100,000sources/64MiB, hydratedcache2,000, root/childbatch50. SQL deadlines/busy waits fit worker slices; normal indexing yields Pending.
- Extract fixed bounded model_config/display_metadata keys inside SQLite; do not return/dump raw config, system_prompt, routing credentials or billing_base_url. Secret-bearing adjacent fields are fixture decoys.
- NULL end is not proof of live work; agent_close proves close, not success. No per-request duration/TTFT/current occupancy proof means speed/active/context Unknown, not message-gap estimates.
- No time/goal/cost matching to invent parent-tool-call→child session IDs. Use explicit edge-bound lineage and actual physical DB identity.
- Synthetic fixtures, content-free Debug and sanitized/masked displays. No automatic commits. Focused red/green/smoke during execution, final full gates only in master. No code/tests run while planning.

## Review Focus

1. Compression inherits delegate markers: presence-only tests must not turn continuation segments into new children or lose descendants spawned by an older parent segment (H2).
2. Default in-place compaction rewinds/clones old rows: preserve compaction-archived history, collapse proven display copies and do not report fake N-new events or infer event costs from aggregate compression spend (H3).
3. Sessions totals and per-model ledger overlap, with auxiliary cost only in the latter: select one main source and add actual nonoverlapping aux once (H2).
4. Same IDs in profile databases, WAL-only rows, locks/corruption and malformed secret-bearing JSON: distinct sources, bounded recovery and no private leakage (H1/H3).
5. An end timestamp or generic agent_close appears after a failed/interrupted child: distinguish closure, recorded finish reason, and inferred activity; never claim success/liveness from absence/presence alone (H2/H3).

## Task H1: Narrow read-only access, metadata and native home/profile sources

**Files:** `sqlite_guard.rs`, Hermes schema/discovery components, existing OpenCode read-only opener only, `tests/hermes_discovery.rs`, synthetic schema helper, existing OpenCode/read-only/privacy/perf tests. No incomplete public Hermes reader registration.

**Consumes:** canonical DbRow identity including database path, metadata/config and worker budgets.

**Produces:** `Allowlist { tables: &'static [(&'static str, &'static [&'static str])], functions: &'static [&'static str] }`; `pub(crate) fn open_read_only_with(path:&Path, allow:&'static Allowlist, busy_ms:u64)->Result<Connection,ProviderError>` in sqlite_guard, preserving existing OpenCode behavior. `ProviderConfig {root,db,extra_roots}` consumption: db is an explicit state.db, root/extra_roots are native Hermes homes. Shared config precedence is explicit CLI db→HERMES_HOME→configured root/db→platform default. Hermes default is `%LOCALAPPDATA%/hermes<suffix>` (fallback userhome/AppData/Local), otherwise `~/.hermes<suffix>`; suffix is literal HERMES_DATA_DIR_SUFFIX. An explicit HERMES_HOME expands only supplied Env user/variable syntax, not shell execution. Enumerate `<home>/state.db` and known `<home>/profiles/<name>/state.db` when the configured home is an unscoped root; if explicitly pointed to a profile, do not widen to siblings. Deduplicate same physical DB via existing same-file identity; no fixed hidden 64-profile truncation. Metadata/file/depth limits remain visible.

Model_config is accessible to fixed internal JSON expressions, never SELECT * or raw public serialization. Treat this as trusted-query discipline: SQLite's column authorizer alone cannot enforce JSON-key privacy. Auth/system_prompt/user_id/base_url and unrelated tables are denied. Malformed/over-budget JSON yields missing optional metadata and a content-free warning, not row loss.

Fixture `tests/support/hermes.rs`: `create_db(path:&Path,current_shape:bool)->Connection` returns an open synthetic writer with WAL/autocheckpoint disabled; `insert_session(conn:&Connection,id:&str,parent:Option<&str>,model_config:Value,started_seconds:f64)`, `insert_message(conn:&Connection,session:&str,role:&str,content:&str,at_seconds:f64)->i64`, `insert_usage(conn:&Connection,session:&str,model:&str,provider:&str,task:&str,token_legs:[u64;5],estimated:f64,cost_status:&str)`; explicit update helpers change known fixture columns. ## Task H2: Explicit logical chains, delegates and aggregate accounting

**Files:** Hermes lineage/usage components, scanner hydration core, `tests/hermes_lineage.rs`, `tests/hermes_usage.rs`, fixture helpers.

**Consumes:** H1 bounded row metadata and shapes, shared typed money/usage/metrics and price engine.

**Produces:** private `HermesRowMeta` with `id,parent,source,markers,started,ended,end_reason` and native DB key; `HermesEdge::{Root,Delegate,Branch,Reset,Compression,Unresolved}`; `classify_edge(row:&HermesRowMeta,parent:Option<&HermesRowMeta>)->HermesEdge`; `resolve_chains(rows:&[HermesRowMeta])->Vec<HermesLogicalSession>` where logical session retains stable earliest root key and member keys root→tip, plus explicit parent/fork relation. Markers are compared with the actual parent ID; ambiguous fan-out/cycles remain inspectable unresolved roots, not guessed chains.

`HermesUsageReconciler::new(meta:SessionMetadata,prices:&PriceSchedule)->Self`, `observe_segment(&mut self,session:&HermesSessionTotals,rows:&[HermesModelTotals])`, `finish(self)->UsageSummary`. The two private totals structs contain source row key, native api-call count, typed token legs, model/provider/task and typed money/status. Define field names from the supported schema projection, not a second source of raw JSON. Each segment selects either complete main per-model rows or its session aggregate plus only separately evidenced excluded auxiliary rows. Never feed Session-scope cumulative rows to request-only UsageLedger or SpeedAccumulator. Details expose aggregate scope with actual api_call_count coverage rather than inventing one request per row.

Money: cost_status actual authorizes actual USD; estimated authorizes saved estimate; included zero is subscription charge, not zero API-equivalent value; unknown/missing status cannot promote default0 into free. Re-estimate aggregates only when proven per-model linear rates suffice; request-dependent tier/time/service pricing requires preserved monetary evidence or missing-request qualifiers, never a tier selected from lifetime tokens or current latest model. Sessions main totals plus main model rows are duplicate alternatives. Compression/title/etc. task rows can add genuinely excluded auxiliary usage once. Parent tool-result quoted child money is not DB spend to add again.

## Task H3: In-place compaction, projected transcript/source and complete reader integration

**Files:** Hermes transcript/scanner, schema projection additions, main/mod registration, `tests/hermes_transcript.rs`, fixture World/acceptance/read_only/privacy/perf suites and public docs.

**Consumes:** H1/H2 metadata/chains/main+aux snapshots, shared ReadProgress and paged detail/UI contracts.

**Produces:** `HermesScanner::new(&Config)->Result<Self,ProviderError>`, `RetryingHermes::open(&Config)->(RetryingHermes,Option<ProviderError>)`, and their complete ProviderReader implementations. `project_hermes_messages(conn:&Connection,members:&[SessionKey],anchor:Option<&PageAnchor>,direction:PageDirection,request:PageRequest,budget:RefreshBudget)->Result<ReadProgress<TranscriptPage>,ProviderError>` is private and resumable. Per-source failure retains last-good metadata/healthy profiles and retries on normal refresh; it never claims an empty successful transcript for a locked DB.

For supported current schema, display rows include active1 OR compacted1. Use existing display_order/display_identity/message_uid evidence to collapse superseded copies, preferring active then latest physical id. Before selecting representatives, build a bounded identity-only removal tombstone set from **every member's** active0/compacted0 rows that carry a proven display identity/message_uid; apply that suppression across the whole compression chain, including archived ancestor copies. A rewind that deactivates a carried child copy must not resurrect an archived parent copy of the same identity, while unrelated archived history stays visible. If display_order is NULL, use a read-only virtual fallback (COALESCE with native id), never call upstream backfill/reconciliation. Preserve source inspection of selected physical rows. Clock regressions cannot reorder native display history: encode anchors in member-chain order plus display-order/id, keeping actual event timestamp as display evidence rather than the sort authority. CountAfter counts projected events, not raw rows copied by compaction.

`_compressed_summary` carriers are observed compaction evidence. Deduplicate proven carrier identities; count only independently observed events and label incomplete history when schema/identity is insufficient. Rotation edges remain explicit compaction observations. A task='compression' aggregate cost is scope Aggregate, not another event and not a per-event split; event before/after/duration remain Unknown unless actually stored. Do not count archived arbitrary message text as a compaction event, or an aggregate ledger row as one event. Retain known compression spend once in session totals and expose it as a breakdown.
