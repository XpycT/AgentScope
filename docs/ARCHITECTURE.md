# AgentScope Architecture

**Status: v1 implemented (2026-11-01). Read-only, privacy, and boundary claims below are covered by `tests/read_only.rs`, `tests/privacy.rs`, and `tests/acceptance.rs` on synthetic fixtures; items marked "future" are not implemented.**

Six harnesses have readers — Codex, Claude Code, OpenCode, OMP (oh-my-pi), Hermes and native Pi — and five of them expose native subagent sessions (all but Pi). Claims are proved on synthetic fixtures through the real readers, worker, `App`, key layer and renderer; real-installation validation is partial (see [PRODUCT.md](PRODUCT.md#implementation-status)). Update this document as components are implemented and their behavior is validated. Requirements and acceptance scenarios live in [PRODUCT.md](PRODUCT.md).

## 1. Local-first architecture

```text
  Codex / Claude / OMP / Pi JSONL ──> native readers ──┐
  OpenCode / Hermes SQLite        ──> DB readers ──────┤
  Claude Desktop manifests/Cowork ──> Desktop reader ──┼──> Normalized records
  OS process snapshot             ──> Process observer┘            │
                                                                   v
                                                        In-memory app state
                                                                   │
                                                                   v
                                                        Keyboard-first TUI
```

**Core boundary:** AgentScope reads external data and never becomes part of agent execution. Hermes and other orchestrators remain untouched. Desktop support is limited to local, accessible native stores; cloud-only or VM-contained history is not discovered.

## 2. Responsibility boundaries

**Provider readers** discover session stores, read safely, interpret only fields evidenced by installed versions, and preserve source provenance. Provider-specific quirks stay within each reader.

**Normalized domain** represents sessions, events, tool interactions, usage observations, and observation confidence. It must preserve unknown/missing fields rather than force a universal shape.

**Usage accounting** interprets provider-specific counters and deduplicates snapshots. It must remain separate from TUI formatting and from optional pricing configuration.

**Process observer** identifies candidate processes and records PID, start time, CPU, memory, and observation time. Process/session matching requires independent evidence; fuzzy candidates must be visibly unlinked.

**Application state and TUI** hold a roster, selection, filters, and transcript navigation. Renderers consume normalized data and should not parse raw provider files on every keypress.

## 3. Minimal domain vocabulary

| Concept | Purpose |
|---|---|
| Harness | The agent product whose local store produced a session (`Harness`: Codex, Claude, OpenCode, OMP, Hermes, Pi). Distinct from a model's billing/routing *provider*, which is recorded text on the model detail and never a harness. All six harnesses have readers today; native Pi extension subagents are explicitly unsupported. |
| Session key | `(harness, native_id, source)`. `source` is a canonical file path or `(database path, table, row id)`, so equal native IDs in different profile databases stay separate sessions. A physical compressed copy is addressed by a locator, not a second key. |
| Session metadata | Cheap discovery facts: title, project, cwd, latest model detail, origin observations, created/activity time with its aggregation class, lineage, archived/released state, source availability. Debug output is content-free. |
| Session summary | Metadata plus usage, lifecycle, and measured `SessionMetrics` (timing, speed, context, compactions). Metrics default to Unknown until an adapter records evidence. |
| Event | Time, event kind, content, provider/source location, stable ID or offset |
| Tool interaction | Tool name, arguments, outcome, linked invocation/result IDs |
| Usage observation | Model, input/output/cache tokens, aggregation scope, provider evidence |
| Process observation | PID + start time + sample time, metrics, possible session association |

The shared reader interface (`ProviderReader`) and the types above are implemented in `src/domain.rs` and `src/providers/`; the vocabulary is intentionally small.

## 4. Read-only and format safety

- **JSONL:** stream complete records; buffer incomplete final lines; detect append/truncate/rotation; bound allocations; unknown or malformed records must not crash the application.
- **SQLite:** open with explicit read-only flags, short bounded queries, and WAL-aware handling. Do not use `immutable=1` to read a live writable database. SQLite may create/update its transient `-shm`/`-wal` sidecars; see [ADR-0002](decisions/0002-opencode-readonly-wal-sidecars.md). Never manually repair, delete, chmod, or copy provider files.
- **Data sourcing:** discover known provider data roots and allow explicit overrides; never read auth files or broad arbitrary directories simply to discover sessions.
- **Rendering:** neutralize ANSI/control sequences and mask common secret patterns by default. No implicit log upload or raw prompt diagnostics.
- **Isolation:** a corrupt or unsupported session must not prevent healthy providers and sessions from being inspected.

## 5. State and measurement semantics

Keep **session lifecycle**, **process observation**, and **activity/health inference** separate. “No new events for 10 minutes” is not proof of a crash, inactivity, or idle state. Explicit terminal events or captured process exit codes provide stronger evidence. Show the reason for each displayed status.

Token records can be cumulative, per-request, or repeated streams. Provider-specific aggregation tests are required before presenting totals. Show `Reported`, `Derived`, `Estimated`, or `Unknown` where appropriate; missing cost must not be displayed as `$0.00`.

Measured facts (`SessionMetrics`) are derived only from recorded fields and never estimated:

- **Timing:** active time is the union of complete turn intervals (overlap counts once); an open or malformed interval makes coverage incomplete instead of extending active time to now. A turn stop is not a session end, so `ended_at`/`elapsed_ms` stay `Unknown` unless the provider recorded a session end.
- **Speed:** whole-request output tokens per second from a recorded duration above 100 ms and recorded positive output; TTFT stays inside the duration and is shown beside it. Weighted throughput covers measured requests and reports `measured/total`; the latest rate keeps the model it was measured on so an older-model rate is labeled, not relabeled.
- **Context:** confirmed prompt occupancy against the applicable window. Lifetime tokens and output never enter the gauge, and a compaction boundary invalidates an older occupancy snapshot until a newer one is recorded.
- **Compaction:** observed event markers, their recorded token reduction, and money from exactly one non-overlapping plane: the full per-event subtotal when every retained event is priced, else a known aggregate amount labeled as not attributed per event (never added to event money), else the partial per-event subtotal labeled as a subtotal rather than a total. Aggregate rows are not counted as extra events, and an unpriced event is never priced by proximity to a nearby request.

Coverage is harness-specific and never generalized from another reader: Codex and Claude Code derive turn timing, prompt context, and compaction markers, with speed `Unknown`; OMP derives summed recorded model time, request speed, active-branch context, and compaction events whose cost stays `Unknown`; Pi derives summed recorded model time, `durationMs` speed, active-path context, and compaction events priced only from retained usage; OpenCode records a creation time but no turn timing, speed, context, or compaction; Hermes records none of active time, speed, or context, and its compaction money is a single aggregate amount.

**Money provenance.** A displayed amount is one of `ReportedApi` (a provider-reported API amount; a reported zero stays reported and does not override the estimate), `SavedCatalogEstimate` (a provider-saved estimate whose source is verified), `UserOverride`, or `BundledReference`; every one is API-equivalent, not billed spend. Subscription allocation, an unverified saved amount, and a parent's quoted child total are never counted. The bundled catalog (`src/pricing/catalog.json`, schema version 1, revision `2026-10-30.2`, checked 2026-10-30) lists every source, priced row and unmapped row. Models, routes, tiers, time-of-day tariffs, unmapped retention rates, and reasoning without an explicit rate stay `Unknown`; a partial subtotal is never promoted to a total.

## 6. Implemented structure and deliberate omissions

- **Threads and channels:** one background worker thread builds and owns every provider reader (`ProviderReader`: resumable `discover`, `hydrate`, `details_page`, `transcript_page`, `count_events_after`, `source_record`, `cancel_read`) and the process sampler. Reader constructors are cheap; filesystem and SQLite opening happens on the worker. The UI thread exchanges `WorkerRequest`/`WorkerEvent` messages over standard-library channels and never parses provider files on a keypress.
- **Metadata-first discovery (exercised):** `discover` walks allowlisted roots resumably and probes a 4 KiB head (header line to 256 KiB) plus a 32 KiB tail per source; OpenCode reads allowlisted session columns only, under a progress-handler deadline. Unloaded bodies are not scanned by discovery; a compressed rollout is probed only through a bounded streaming header window (a prefix timestamp supplies activity when present, otherwise mtime) and is indexed on demand. `RosterIndex` keeps one `SessionMetadata` per source (default 100,000 sources / 64 MiB; at the ceiling the newest sources are kept and `Discovery limited` is shown, never EOF) and a separate, `max_cached_sessions`-bounded cache of hydrated summaries. The first discovery generation freezes the ranked root order; roots load 50 at a time and children 50 per batch. Later sources, deletions and edges only raise "refresh available" (deleted members stay Unavailable) until an explicit refresh. The first 50 roots are hydrated by a work iterator, not by the 16-slot load queue. Roster search, filters, and counts cover loaded roots plus loaded children (a matching child keeps its parent row); unloaded sessions are never reported as absent. Transcript search covers the loaded event window, and `m` reveals the next 50 roots.
- **Bounded work:** adapter work is sliced by a budget of 256 records, 8 MiB and 100 ms; the Hermes message projection also runs its display/tombstone SQL under that deadline and folds identities in resumable slices; `ReadProgress::Pending` is normal progress and continuation state is keyed by `(SessionKey, ReadJobId)`, so cancelling one purpose never releases another's work. Discovery, hydration, transcript indexing, `count_events_after` and OpenCode `details_page` (the request scan and the recent-event pager both count examined rows and bytes, cross rows that yield nothing, and enforce the page allowance across slices) stop at the record or byte allowance and resume; OpenCode queries also carry a progress-handler deadline. The 100 ms limit is checked between units of work (records, directory-entry batches, rows), so one very large record or a slow filesystem call can run past it: it is a scheduling target, not a hard real-time guarantee. Reading an already indexed transcript page, and OpenCode transcript pages, are bounded by the page size (events/bytes) rather than by the slice allowance. Page size, record size, loaded-event count and the Claude dedup ledger are capped, with tests in `tests/perf_budget.rs`, `tests/bounded_reads.rs` and `tests/review_fixes.rs`.
- **Adapter bookkeeping:** each adapter keeps at most `max_metadata_sources` / `max_metadata_bytes` of per-source discovery state (newest first; an updated source is re-admitted under the same age rules, so growth never evicts newer sources). Eviction only forgets bookkeeping and is never reported as a removal. Evicted sources go into a bounded "forgotten" set (4,096): a frozen row or in-flight read on one stays readable only while the file still carries the published session identity (the head probe is re-checked, so a replaced file or an unknown ID is refused), and each pass checks that those sources still exist so a genuine deletion reaches the roster. Only a confirmed absence (`NotFound`) counts as a deletion; other I/O errors keep the watch and warn. Eviction never disposes of read state an active job is consuming. OpenCode checks forgotten sessions in a budgeted, resumable sweep and retains findings until a delta delivers them. **Bound consequence:** beyond 4,096 evictions the oldest forgotten sources lose both deletion watching and fallback readability; such a frozen key fails closed (the read is refused, never served unauthorized) until a refresh re-discovers it. Live transcript indexes (at most 8) are never discarded; a ninth concurrent job waits `Pending` until a completed index can be dropped.
- **Details and counting:** OpenCode `count_events_after` and `details_page` are resumable per job. Details pages share one record/byte allowance across request observations, compactions and recent events; each returned record consumes it once. OpenCode request observations come from assistant messages with recorded tokens (v2 schema only) and OpenCode records no compaction markers; Claude request observations are the usage each paged message recorded; Codex records cumulative usage only and reports no requests. These are shown in the roster help ("Capability limits").
- **OpenCode identity and links (exercised):** the allowlisted `session_v2.agent` column records the agent role; the `model` JSON supplies the model id, billing route (`providerID`), and raw `variant`, with effort reported only for observed thinking-level spellings. A missing provider stays `Unknown` and unpriced. A tool call links to a native child only from v2 `subagent` metadata `sessionID` or legacy `task` metadata `sessionId` (case-sensitive, never parsed from output text), and the UI resolves it among sessions of the same database. A fork (`parent_id` null, `fork_session_id` set) is a root, and parent/child/nested usage and cost stay separate. Other session metadata columns and JSON members are denied or unread.
- **Claude native children and local Desktop sources (exercised):** a Claude project root yields `<project>/<session>.jsonl`; native subagents are `<project>/<session>/subagents/**/agent-<id>.jsonl` and nothing else under them (workflow `journal.jsonl`, tool-result files and sidecars are never sessions). A child's identity is its `agentId` (the file name, confirmed against an optional `agent-<id>.meta.json` sidecar), never the parent `sessionId` its records repeat; its parent comes from the session directory plus a nested `parentAgentId` resolved inside the same subagent tree, never from `parentUuid` (a message UUID) or from cwd/time. Direct usage counts only records stamped with the child's own agent, so inherited/copied history and shared message IDs never enter a child's total and inline sidechain records never count as parent usage. Claude Desktop Code uses the same project store: allowlisted `claude-code-sessions/**/local_*.json` manifests enrich an existing transcript by `cliSessionId` (entrypoint, archive flag, release/delete markers) and never create a session; Cowork's `local-agent-mode-sessions/<a>/<b>/local_*/…` Claude-format project roots are walked as ordinary roots and labeled `Cowork` from the layout. Only those shapes are located: `host-creds-*.json`, `ccd-session-secrets/`, `IndexedDB/`, `Local Storage/`, session `audit.jsonl`/`.audit-key` and `vm_bundles/` are never opened. `entrypoint` values map only when confirmed (`cli`, `claude-desktop`, `claude-vscode*`, `claude-jetbrains*`, `sdk-*`); other values stay `Unknown` with their raw text. Released sessions (a boolean flag or a present timestamp marker) are hidden behind the roster's explicit "Include released sessions" filter and are never deleted or rewritten; an unconfirmed marker shape leaves the release state `Unknown`. Platform defaults are fixture-backed only (`%APPDATA%\Claude`, `%LOCALAPPDATA%\Claude-3p`, legacy roaming `Claude-3p`, macOS `Application Support`, XDG `~/.config`), overridable with `--claude-desktop` / `[providers.claude_desktop]`; the proprietary desktop app was not run.
- **Codex children, provenance and archives (exercised):** Codex discovers both native rollout stores under `CODEX_HOME` (`sessions` plus `archived_sessions`), or the explicit roots configured, never a WSL/remote path. Plain `.jsonl` and native `.jsonl.zst` copies are read with the same streaming reader; the key is the canonical plain path, and a live/archived or plain/zstd copy of one rollout file name in the same native store is one logical session (a confirmed key survives compression and archival, and later locators name the current physical file and generation). The first `session_meta` is the identity; only a recorded immediate `parent_thread_id`/`thread_spawn` makes a parent edge (`session_id` is the root thread, never promoted), a guardian review keeps its role without a parent edge, and an unsupported version keeps a recorded history boundary untrusted. Usage is owned by ordinal against `subagent_history_start_ordinal`: copied parent counters are the inherited baseline (or a child-local reset), so a replayed prefix never becomes child spend; without trustworthy evidence the child reports no confident total, partial coverage and a visible `#usage-boundary` warning. Origins are labeled from `source`/`originator` only where those distinguish the CLI, Desktop app and IDE extension; `vscode` with an ambiguous originator stays `Unknown`. Ignored: `auth.json`, arbitrary `CODEX_HOME` subtrees, and any path outside the configured roots.
- **Hermes reader (implemented, synthetic):** native `state.db` homes/profiles, compression chains and rotation/in-place compaction are read read-only through a narrow allowlist. Display rows include `active=1 OR compacted=1`; proven stored identities collapse copies and a newest-removed-copy tombstone prevents a rewind from resurrecting an archived parent copy. `_compressed_summary` carriers and rotation edges are Event-scope compaction evidence; a `task='compression'` ledger row is one Aggregate-scope amount, never split per event. Request speed, live context and per-event compaction before/after/duration stay Unknown. No Hermes tool metadata records a child session, so no tool-call→child jump is shown.
- **Integrated native closure (exercised on synthetic fixtures):** the five native readers (OMP and Pi included) plus the Hermes reader, the worker, `App` and the renderer are proven together on one 125-root store with nested families, forks, Claude Desktop Code/Cowork/released sessions, zstd and truncated archives, partial and damaged records, an unrecorded billing route, injected secret fields and a locked WAL database (`World::native` in `tests/support/world.rs`). Root pages are exactly the 50/100/125 newest *groups* (a group's activity is the newest of its own and its descendants'; children never become roots and a fork is its own group); each member reports only the tokens and cost it owns, a child opens like any session, a session opens at its newest entry, and a response for an older generation or request is dropped. A truncated archive keeps its readable prefix and one source-scoped diagnostic; a locked WAL database is `Unavailable` and retried while the other readers stay listed. Honest limits: Claude Desktop chat history is not reconstructed (only Code manifests and Cowork project stores are read), WSL/remote/cloud histories are not discovered, and Pi extension subagents are unsupported (the native format records no child sessions). Further readers join through the same `ProviderReader` contract; the world's expectations are not rewritten for them.
- **OMP sessions (exercised on synthetic fixtures):** `OmpScanner` (`src/providers/omp/scanner.rs`) is the fourth native reader. Discovery is `OmpCatalog` (prefix/tail probes of the known `<root>/<bucket>/<session>.jsonl` layout and artifact directories; no blobs, symlinks or other agent-directory stores), relationships come from artifact shape plus header evidence, lifetime facts from `OmpHydration` (owned-request ledger across branches, active-leaf model/effort/context, compactions without cost). The reader keeps at most 16 hydrations, `max_cached_sessions` summaries and 8 transcript indexes. An index holds one row per event (timestamp, `member/offset/block` order key, entry ID, counted-request flag), never a body; it is built in budgeted slices that answer `Pending`, polled for appends and voided when a member is truncated or replaced. Pages read events back by offset through `SourceReader`, whose generation guards every locator (a stale locator is a terminal error). A request is attached to an event only when this session owns it (`OmpHydration::ownership`) and it is the first occurrence, so fork/continuation copies are shown but never counted again. A continuation chain's members are indexed as one logical session. Details pages share one allowance across requests, compaction markers (with bounded recorded summaries) and events. `cancel_read` drops only an unfinished hydration or index once no other job needs it. A session-init record (system prompt, task) is shown as a fixed label. One call spends at most one budget.
- **Native Pi sessions (exercised on synthetic fixtures):** `PiScanner` (`src/providers/pi/scanner.rs`) is the fifth native reader. Discovery is `PiCatalog` (bounded prefix/tail probes of `<root>/<bucket>/<name>.jsonl` only; no extension blobs, nested directories or agent-directory stores), lifetime facts from `PiHydration`, and the fork edge is resolved only among discovered sources. A session is one JSONL file; the index holds one row per displayed event (entry timestamp, `ordinal << 16 | block` order, native entry ID, counted-request flag) and never a body, is built in budgeted `Pending` slices, continues after append-only growth, and is voided when `SourceReader` reports truncation/replacement. Locators carry the index instance, so a record listed before a replacement stays stale. A recorded call is attached only when `PiHydration::ownership` proves this file owns it and it is the first occurrence, so a fork's copied prefix is listed but not charged. A trailing partial line is `Incomplete`, never an event, until its terminator arrives. Details pages share one record/byte allowance across requests, compaction/branch-summary markers (bounded recorded summaries, recorded summary usage when owned) and recent events. Extension state (`custom`) is a diagnostic; a `custom_message` appears only when the producer marked it displayable; no extension child row is invented.
- **Known limits:** a source's key comes from the discovery probe, so a Claude session ID that only appears beyond the probe windows keeps the file-name key and is flagged "Approximate session ID". OpenCode per-session activity uses the newest 256 message rows and an activity count that saturates at 100,001, so one query cannot outlive a slice. Directory enumeration is batched, but a directory's names are sorted once fully listed, so a directory with millions of matching entries still holds all of those names in memory. Real-hardware benchmarks remain in the benchmark note.
- **Deliberately absent:** event bus, daemon, remote API, cache database, async runtime, network access, and any provider write path.

## 7. Future expansion (out of MVP)

For multiple machines, each host could run a read-only collector reporting to an authenticated hub, with encrypted transport and optional transcript sharing. The same normalized vocabulary and TUI may remain useful. This is an architectural direction, not a committed API or supported feature.

For orchestrator integration, correlation between Hermes tasks and provider sessions must come from explicit persisted identifiers or a consented integration. Do not infer lineage from time or directory alone.
